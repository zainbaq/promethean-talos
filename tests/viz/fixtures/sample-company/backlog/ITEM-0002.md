## Description

Why P0: without saved settings the Timer has nothing to read and criterion 3 cannot pass; the charter fixes two items, one per screen. Charter goal, criteria 3, 4, 5, 6. Scope: a Settings screen with three controls: focus length (minutes), break length (minutes) and sound on/off. Values persist across a page reload in browser-local storage (localStorage or equivalent; the Chief Architect decides) with no backend and no network calls. The Timer screen reads the saved focus length so that after a reload it shows the saved value (30 -> 30:00) before Start. Light and dark mode. Built in parallel with the Timer item (same cycle, two engineers): shared files such as the app shell, design tokens and the settings storage module are the Chief Architect's to assign in the spec; this item does not decide the stack, storage key names or file layout. Non-goals: accounts, sync, themes beyond light and dark, long-break settings, pomodoro counts.

## Acceptance criteria

- [ ] (Charter 3) On the Settings screen set focus to 30, break to 7 and sound off, then reload the page; the Settings screen shows focus 30, break 7 and sound off.
- [ ] (Charter 3) After that reload the Timer screen shows 30:00 before Start is pressed, and Reset on the Timer returns to 30:00.
- [ ] (Charter non-goals) Each setting change takes effect without any network request (Playwright records zero network requests other than local file or local server loads).
- [ ] (Charter 4) At 390 px width, in light and in dark mode, there is no horizontal scroll and the focus length, break length and sound controls are all visible without scrolling.
- [ ] (Charter 6) axe-core reports zero serious or critical violations on the Settings screen in light mode and in dark mode.
- [ ] (Charter 6) Every Settings control is reachable by Tab, operable by Enter or Space (or arrow keys where the control type requires it), and shows a visible focus ring when focused.
- [ ] (Charter 5) Captures of the Settings screen at 390x844 and 1280x800 in light and dark (`tools/talos/screens.py`) are signed by Design QA as matching the approved mockups.
