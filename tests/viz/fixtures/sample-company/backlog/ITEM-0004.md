## Description

Why P3: hardening, no user-visible failure seen in cycle 1. Code review nit on ITEM-0001 (EVT-20261028173020-175e): app/timer.js line 90 calls audioCtx.resume() without handling the returned promise; if a browser rejects the resume (autoplay policy, device change) the rejection is unhandled and shows up as a console error, which hides real errors from the Test Engineer and alarms anyone opening devtools. Charter risk: sound playback may be blocked by autoplay rules. Scope: app/timer.js and tests/test_timer.py only. The Chief Architect decides whether to catch and ignore, catch and disable sound for the session, or something else.

## Acceptance criteria

- [ ] A Playwright test stubs AudioContext.prototype.resume via page.add_init_script to return a rejected promise, enables sound in localStorage, then presses Start, Pause, Start; page.on("pageerror") and console messages of type error record zero entries, and the countdown still runs (#count decreases within 2 s).
- [ ] With the stub removed, the same flow records zero page errors and zero console errors.
- [ ] All existing tests in tests/test_timer.py still pass with 0 skipped.
