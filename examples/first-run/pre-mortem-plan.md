# Pre-mortem: plan for wordstat

**Author:** Learning Officer · **Date:** 2026-10-25 · **Input:** charter.md (approved EVT-20261025155321-7732), Q-0001/Q-0002 answers, `knowledge/INDEX.md` (empty).

No recorded lessons exist yet, so every entry below is a generic risk for this shape of build: a stdlib Python CLI, two Sonnet engineers in parallel inside one 30-minute cycle, specs by the Chief Architect, verified by the Test Engineer. Each entry names what breaks, which part of the plan it threatens, and what the specs must say. The Chief Architect addresses every entry or records why not.

1. **Two engineers edit the same file.** Threatens: the whole cycle (merge conflict eats the 30 minutes). Specs must assign disjoint file lists per item (e.g. `wordstat/core.py` + `tests/test_core.py` to one, `wordstat/cli.py` + `tests/test_cli.py` + `README.md` to the other) and name who creates `wordstat/__init__.py` and `wordstat/__main__.py`. No file appears in two specs.
2. **Core/CLI interface drifts between the two engineers.** Threatens: CLI item, test item. The spec must write the function signature verbatim, e.g. `count_words(text: str) -> Counter[str]` and `top_words(counts, n: int) -> list[tuple[str, int]]`, with return order defined (count desc, word asc). The CLI engineer imports only those names.
3. **"Handle errors" without exit codes.** Threatens: success criterion 7, CLI tests. Spec must state: missing/unreadable path -> message on stderr containing the path, exit 1; argparse errors keep argparse's exit 2; success exit 0. Name the stderr message format.
4. **`--top 0` and negative `--top`.** Threatens: criterion 2, CLI tests. argparse accepts `--top -3` as an int. Spec must choose one: reject `n < 1` with exit 2 via a custom `type=` function, or print nothing for 0. Pick, write the exact error text, and add a test for both `0` and `-1`.
5. **`--json` and table disagree on order or content.** Threatens: criterion 3. Spec must make both formatters consume the same `top_words(...)` list; the JSON shape is fixed as `[{"word": ..., "count": ...}, ...]` (array of objects preserves order; a dict would not under 3.8 semantics readers assume). Test compares `json.loads` output against the parsed table rows.
6. **Table alignment differs between what the engineer writes and what tests assert.** Threatens: criterion 1, CLI tests. Spec must give the exact format: word column left-aligned padded to the longest word, count column right-aligned padded to the widest count, single space separator, no header, no trailing whitespace, `\n` line endings. Include one literal expected-output example in the spec.
7. **Empty file prints a header, a blank line or `{}`.** Threatens: criterion 7. Spec must state: empty input -> zero bytes on stdout for the table, exactly `[]\n` for `--json`, exit 0. Test asserts byte-exact.
8. **Tokeniser ambiguity: "letter or digit" and Unicode.** Threatens: criteria 4, 5, 6 and the Q-0001 default. Spec must name the predicate (`str.isalnum()` on each character, then `str.lower()`) and whether `casefold()` is used. Note the known 3.8 wrinkle: `'ß'.lower()` differs from `casefold()`. State one; the charter allows one simple Unicode test case only.
9. **Whitespace splitting done with `split(' ')` instead of `split()`.** Threatens: criterion 6. Spec must say `text.split()` (no argument) and give the `a  b\tc\nd` fixture as an acceptance test.
10. **Tests pass in a worktree, fail from a clean checkout.** Threatens: criterion 8, release gate. Causes: relying on an installed package, `conftest.py` path hacks, fixture files not committed, absolute paths. Spec must require `python -m pytest` from repo root with no install step, tests that invoke the CLI via `subprocess.run([sys.executable, "-m", "wordstat", ...])`, fixtures written to `tmp_path` not checked-in files, and the Test Engineer runs it from a fresh `git clone`/`git worktree add` of the merged branch.
11. **File encoding on Windows.** Threatens: criteria 4, 5, 8 (the CEO runs Windows; default encoding is cp1252). Spec must require `open(path, encoding="utf-8", errors="replace")` for input, keep `json.dumps` at its default `ensure_ascii=True` so stdout stays ASCII-safe on any console, and have tests write fixtures with explicit `encoding="utf-8"`.
12. **Line endings in subprocess test assertions.** Threatens: CLI tests on Windows. Spec must require tests to use `text=True` and compare after `.splitlines()` or normalise `\r\n`, never raw string equality against `"\n"`-joined output.
13. **Python 3.8 compatibility silently broken.** Threatens: charter constraint, criterion 10. Sonnet defaults to 3.10+ syntax (`list[str]` at runtime, `match`, `X | None`). Spec must forbid runtime use of PEP 585/604 generics (or require `from __future__ import annotations`), forbid `match`, and the Test Engineer greps for them. Name the interpreter the tests run on.
14. **A third-party import sneaks in.** Threatens: criterion 10. Spec must list the permitted modules (`argparse, collections, json, sys, pathlib`) and require a test or check that `grep -E "^(import|from) " wordstat/*.py` matches only those.
15. **Spec gives acceptance criteria that are not executable.** Threatens: handoff contract, test item. Every criterion in a spec must be a pytest test name or a shell command with expected stdout/exit code. "Prints a nice table" is rejected at handoff.
16. **Engineers guess instead of stopping.** Threatens: every item. Each spec must include a short "if unclear, stop and ask" list of the known-ambiguous points (3, 4, 8 above) with the decision already written, so there is nothing left to guess.
17. **README example drifts from shipped output.** Threatens: criterion 9, definition of done 3. Spec must require the README examples to be generated by running the tool on a committed `examples/sample.txt` (one tiny committed fixture is acceptable here) and a test that runs the README command and compares.
18. **`python -m wordstat` vs `wordstat` entry point confusion.** Threatens: criteria 1, 9. No packaging is in scope, so there is no `wordstat` console script. Spec must state the invocation is `python -m wordstat file.txt` (or `python wordstat.py`) and the README uses exactly that form; the charter's `wordstat file.txt` shorthand is explained once.
19. **Budget overrun by over-engineering.** Threatens: 30-minute cycle. Spec must cap each item (charter says under 40 lines per item) and forbid classes, logging, config, type-checking tooling and any flag not in the brief. Reviewers reject additions not traceable to a criterion.
20. **Review findings arrive with no owner or no re-test.** Threatens: release gate. Plan must state that after review fixes, the Test Engineer re-runs the full suite from a clean checkout before `company gate release`; a green run before the fix is not evidence.
